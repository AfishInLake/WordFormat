# 领域包开发指南

领域包（Domain Pack）是 WordFormat 的插件单元：**一个自包含目录 = 一个文档领域**。
开发新领域（公文、计划书、材料……）只需写三样东西 —— 节点（node）、分类后处理（postprocess）、事件回调（hook），
全部通过注册机制挂到框架上，**不触碰框架核心代码**。

> 架构背景见 [领域包拆分可行性分析](领域包拆分可行性分析.md)（缝 A/B 已于 2026-09-29 落地）。
> 现有论文领域是最完整的参考实现：`src/wordformat/domains/thesis/`。

## 目录结构（模板）

```
src/wordformat/domains/<name>/
├── __init__.py          # 入口：@register_domain 声明 + register_handlers(registry)（hook 事件）
├── rules/               # 节点：FormatNode 子类，@register 注册
│   ├── __init__.py      #   聚合导出本领域节点
│   └── your_node.py
├── postprocess.py       # （可选）分类后处理整链：register_postprocess("name", fn)
└── model/               # （可选）领域独立模型：model_info.json + id2label.json + onnx
```

放置好后，框架通过 `domains/__init__.py` 的 pkgutil 自动发现导入该包——**无需任何注册清单**。
仅当需要显式装配事件回调时调用 `load_domain("<name>")`（幂等，重复调用只装配一次）。

## Step 1：注册领域入口（__init__.py）

```python
# src/wordformat/domains/gongwen/__init__.py
from wordformat.domains import register_domain
from wordformat.hooks import HookRegistry

# 导入即注册分类后处理整链（若本领域提供）
from . import postprocess as _postprocess  # noqa: F401


@register_domain("gongwen")
def register_handlers(registry: HookRegistry) -> None:
    """将本领域的格式化链路差异注册为事件回调。"""
    registry.register(
        "on_tree_normalize", _promote_tree, name="gongwen.tree_normalize"
    )
```

## Step 2：开发节点（rules/）

节点决定"每个段落类别该长什么样"。一个节点 = 类别身份（@register）+ 样式默认值（DEFAULTS）+ 检查/应用逻辑（RULES）。

```python
# src/wordformat/domains/gongwen/rules/heading.py
from wordformat.config.dotdict import BASE_FORMAT, deep_merge
from wordformat.rules.node import FormatNode
from wordformat.structure.registry import register


@register("heading_level_1", level=1)   # ← 类别名 + 树层级（公文可以是 level=1..4）
class HeadingLevel1Node(FormatNode):
    NODE_TYPE = "headings.level_1"       # ← YAML 配置点分路径（见 Step 5）
    NODE_LABEL = "一级标题"
    DEFAULTS = deep_merge(               # ← 样式默认值，与 BASE_FORMAT 合并
        BASE_FORMAT,
        {
            "paragraph": {"alignment": "justify", "first_line_indent": "0字符"},
            "font": {"font_size": "二号", "bold": True},
            "spacing": {"before": "0磅", "after": "0磅"},
            "rules": {"my_check": {"enabled": True, "threshold": 3}},
        },
    )
    RULES = {"my_check": "_handle_my_check"}   # ← 业务规则：规则名 → handler 方法

    def _handle_my_check(self, doc, rule_cfg, p: bool = False):
        """只管判断，enabled 已由框架过滤。结果通过 add_comment 上报。"""
        count = len(self.paragraph.text)
        if count < rule_cfg.threshold:
            self.add_comment(doc=doc, runs=self.paragraph.runs,
                             text=f"标题过短（最少 {rule_cfg.threshold} 字）")
```

要点：

- **复用通用节点**：正文 / 题注 / 图 / 表 / 公式节点已在核心 `wordformat/rules/`（body、caption、object、math、heading）。公文如果只是 DEFAULTS 不同，可以继承通用节点改默认值，不必重写。
- **注册表实例**：`@register` 注册到默认领域表（论文默认装配）。多领域共存时用 `get_registry(domain)` 拿本领域独立实例：
  `get_registry("gongwen").register("heading_level_1", level=1)(HeadingLevel1Node)`；
  树构建已支持 `registry` 参数（`create_node(..., registry=reg)` / `DocumentTreeBuilder(registry=reg)`），避开同名类别互相覆盖。
- 聚合导出：`rules/__init__.py` 导出本领域所有节点类（触发顶层 `@register` 的组装点之一）。

## Step 3：分类后处理（postprocess.py）

分类（`DocxBase.parse()`）之后需要一个领域整链修正器（阈值应用 + 位置规则 + 序列约束等）。
协议是**整体替换**语义——整链函数，不是布尔开关列表。

```python
# src/wordformat/domains/gongwen/postprocess.py
from typing import Callable

from wordformat.agent.onnx_infer import get_thresholds
from wordformat.domains.postprocess import register_postprocess


def _apply_threshold(item: dict) -> None:
    """阈值优先级：领域模型元数据 → 全局缓存 → 内置兜底。"""
    thresholds = get_thresholds("gongwen") or _CONF_THRESHOLDS
    if item["score"] < thresholds.get(item["category"], thresholds.get("default", 0.5)):
        item["needs_review"] = True


def _gongwen_postprocess(result: list[dict]) -> list[dict]:
    """公文分类后处理整链（顺序很重要）。"""
    for item in result:
        _apply_threshold(item)
    # ... 你的规则 ...
    return result


# 模块导入即注册（与 @register 同构）；框架分派 get_postprocess("gongwen")
register_postprocess("gongwen", _gongwen_postprocess)
```

分派行为：`get_postprocess(domain)` 未注册的领域返回 `None`，`parse()` 直接跳过该环节——新领域不写 postprocess 也能跑。

## Step 4：事件回调（hook）

| 事件 | 时机 | 论文领域用法（参考） |
|---|---|---|
| `on_tree_normalize` | 树构建后 | 子树提升（摘要/参考文献区 body → 类型化节点） |
| `on_format_begin` | 格式化开始 | 题注章节号 / 序号计数器重置 |
| `before_node_format` | 每个节点格式化前 | 题注编号注入 |
| `after_node_format` | 每个节点格式化后 | — |
| `on_summary_build` | 报告摘要 | 摘要统计（字数/关键词/参考文献规范） |
| `before_document_save` | 保存前 | 编号 / 超链接等收尾 |
| `on_comment` | 批注生成 | 自定义批注 |

```python
# 回调签名：callback(event_data: dict) -> dict | None（返回 dict 时合并进事件数据）
def _promote_tree(data: dict) -> dict:
    # data["root_node"] / data["config"] / data["check"]
    return {"root_node": data["root_node"]}   # 需要替换时返回新值
```

回调名用 `"<domain>.<逻辑名>"` 前缀，预设可通过 `hooks.unregister(event, name)` 精确定位禁用。
装配顺序（`pipeline/orchestrate._prepare_hooks`）：**内置机制 → 领域 → 预设（最后注册可覆盖一切）**。
当前编排入口默认装配 `thesis`；新领域接入时在编排入口按 `document_type` 选择 `load_domain("<name>")`。

## Step 5：YAML 样式配置

YAML 只承担样式配置，**不写分类标签 / 阈值**（那是模型属性，见 Step 6）。
节点经 `NODE_TYPE` 点分路径自动从 YAML 取配置并合并 DEFAULTS：

```yaml
# 与 NODE_TYPE = "headings.level_1" 对应
headings:
  level_1:
    <<: *global_format
    paragraph: { alignment: justify, first_line_indent: 0字符 }
    font: { font_size: 二号, bold: true }
    rules:
      my_check: { enabled: true, threshold: 3 }
```

用 `wordf config -o` 可导出全量模板（遍历注册表按 NODE_TYPE 重建）。

## Step 6：（可选）领域独立模型

模型文件放进 `model/` 目录即被自动发现（约定优于配置，无需注册）：

```
domains/gongwen/model/
├── model_info.json      # onnx 文件名 / max_length / thresholds（分类阈值）
├── id2label.json        # 标签表（模型自身的标签集）
├── tokenizer.json
└── *.onnx
```

- `get_thresholds("<name>")` 优先读本领域 `model/model_info.json` 的 `thresholds`，未提供时回退全局模型缓存；
- 论文等内置领域未放领域内模型目录，沿用 `wordformat/data/model/`（默认路径）；
- **已知边界**：推理侧目前仍是单模型全局缓存（`agent/onnx_infer._load_model`）。首个带独立模型的领域接入时，需将该函数改为按领域目录加载并引入多模型缓存——接口（`_get_model_dir` / `_read_model_info`）已就位。

## Step 7：测试与验证

- 节点测试放在 `tests/domains/test_<name>.py`（参考 `tests/domains/test_thesis.py`）：
  事件测试用独立 `HookRegistry()` 装配本领域，不污染全局 hooks（`_registry_with_thesis()` 模式）；
- 后处理测试直接 import 整链与规则函数（参考 `tests/classify/test_tag.py::TestPostProcessing`）；
- 注册表测试用 `Registry()` 独立实例验证类别解析（参考 `tests/test_integration.py::TestNodeFactoryIntegration::test_create_node_with_domain_registry`）。

## 注意事项

- **不要改框架代码**。机制层（注册表 / Hook / 流水线 / 配置）不因新领域而变；有缺失先评估是否属于 §核心职责（见可行性分析 §3.1）。
- **整链语义**：后处理、hook 回调都是"整体替换"，不是开关列表——改一条规则 = 提供一个新的整链实现。
- 后处理扩展标签（`other` / `document_title` / `footer` / `heading_mulu` / `heading_fulu`）的占位映射目前随论文默认装配（`structure/settings.py` 的 setdefault 块），新领域按需自备。
- **前端双写**：`WordFormatUI/src/composables/useTagHelpers.js` 仍持有类别阈值副本（已实测漂移），后端权威来源已迁移到模型元数据；UI 侧 schema 供给（缝 D）落地前，新类别的前端展示需手动同步。
- 参考文件：节点机制 `rules/node.py`；注册表 `structure/registry.py`；分派 `domains/postprocess.py`；论文领域全量实现 `domains/thesis/`。
